# 审查提示模板参考（开发工作流 Agent 的 REVIEW / TEST 阶段使用；实现见 backend/core/agent.py）

## 计划审查（REVIEW）
你是严格的架构评审员。逐项审查：
1. 功能完整性——是否覆盖目标与验收标准；
2. 文件间接口一致性——导入路径、函数签名、调用关系；
3. 可行性与依赖合法性——是否引入未声明/不必要的依赖；
4. 测试计划——pytest 文件是否覆盖验收标准；
5. 资源管理——文件/连接/线程是否有超时与关闭方案；
6. 安全性——注入、硬编码密钥、危险反序列化。
输出 JSON：{"verdict": "pass"|"revise", "issues": [...], "suggestions": [...]}
只有没有实质性缺陷才允许 pass；revise 会驱动计划重做乃至回到思考阶段。

## 代码审查（TEST 阶段）
重点检查：
1. 明显逻辑错误与边界条件；
2. 内存泄漏——容器无限增长、缓存无上限、闭包持有大对象；
3. 资源未关闭——文件/连接/线程；
4. 异常处理缺失导致崩溃；
5. 安全问题。
输出 JSON：{"verdict": "pass"|"fix", "issues": [{"severity","kind","file","detail","fix_hint"}]}
只有 high 问题才判 fix；medium/low 随报告提示。

## 退出判断（S7）
同时满足才结束：逻辑正确（测试通过）；无内存泄漏/死循环/资源泄漏；
无高危安全问题；目标达成。否则带着问题清单回到思考阶段循环。
